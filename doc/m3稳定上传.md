# 模块 M3 接口契约：文档上传

## 1. 目标（一句话）
登录用户上传 PDF/文本 → 文件安全落盘 + documents 表记录（status=pending）→ 能查自己的文档列表和详情。
解析/切块是 M4 的事，M3 不做。

## 2. 目录增量（M2 基础上新增）
app/
├── models/document.py        # Document 模型（第一次写外键）
├── schemas/document.py       # DocumentOut
├── services/storage.py       # ★ 校验+落盘+建记录（你第一个 service 层）
└── api/v1/documents.py       # 上传/列表/详情路由
uploads/                      # 文件存储目录（记得加进 .gitignore）
tests/test_documents.py

## 3. 数据模型
documents 表：
- id: int, PK, 自增
- user_id: int, FK → users.id, not null, index   # 归属：只能看自己的
- filename: str(255), not null                   # 原始文件名（仅展示用）
- stored_path: str(255), not null                # 落盘路径 uploads/{user_id}/{uuid}.{ext}
- size: int, not null                            # 字节数
- status: str(16), default "pending"             # M4 做流转，M3 只保证初始值
- created_at: datetime, server_default now()

## 4. API 契约
POST /api/v1/documents          # multipart/form-data，字段名 file，需鉴权
  响应 201: {"id":1,"filename":"a.pdf","status":"pending","size":12345,"created_at":"..."}
  错误: 401 未登录 / 415 非 pdf/txt/md / 413 超 10MB / 422 缺 file 字段

GET /api/v1/documents           # 需鉴权
  响应 200: [...]  # 只含当前用户的文档，按 id 倒序

GET /api/v1/documents/{id}      # 需鉴权
  响应 200: {"id":1,"filename":"a.pdf","status":"pending","size":12345,"created_at":"..."}
  错误: 401 / 404（不存在或不属于当前用户，统一 404，不泄露存在性）

## 5. 验收标准（DoD）
- [ ] documents 表含 user_id 外键
- [ ] 上传 .pdf → 201，且 uploads/{user_id}/ 下真实存在 uuid 命名的文件
- [ ] 未登录上传 → 401
- [ ] 上传 .exe → 415；>10MB → 413
- [ ] 文件名含 ../ 或中文 → 正常落盘（uuid 重命名，不直接用用户文件名）
- [ ] 造两个用户：互相看不到对方文档（隔离验证）
- [ ] GET /documents/{别人的id} → 404
- [ ] pytest ≥5 个测试全绿
- [ ] v2 方法三件套：报错先猜 3 原因 / 三问复盘写进 doc/m3文档上传.md / 合上代码重写 save_upload

## 6. 技术约束
- 新依赖：python-multipart
- 存储：本地 uploads/，按用户分目录；文件名用 uuid4 重命名，原始名只存库
- 大小 10MB；类型白名单 pdf/txt/md（扩展名判断，MVP 够用）
- ★ 校验+落盘+建记录必须放 services/storage.py，路由只做 HTTP 编排（≤20 行）
- 禁止用现成上传库

# 复盘

## 问题1：解决了什么问题？不用它会怎样？
### M3 解决的是「外部数据进入系统」的入口 + 归属问题
→ 让系统能收用户提供的文件。安全边界有数据不可信，扩展名，大小，文件都可能是恶意，数据大小，编码，内容格式不可控的问题需要考虑
所以所有的校验都是在做这个事情。

### 建立「归属」模型
documents.user_id 外键是第一个真正的资源归属关系。M2 的 user 是「自己」，M3 的 document 是「谁的」。
这个模式会贯穿后续所有模块：
  M4 的 chunk 归属 document
  M5 的 embedding 归属 chunk
  M6 的检索结果归属 user
M3 是「多用户数据隔离」的第一次落地。为后续提供稳定的输入契约，m4不关心文件怎么来的，只关心哪有文件，m3校验完后，m4直接使用

### 不用它会怎样？——分三层
表层：没有文件，RAG 没数据。
中层：如果只做「接收但不落盘」，M4 要自己处理文件；
     如果只做「落盘但不建记录」，M4 无法知道「哪些文件属于谁」；
     如果只做「建记录但不校验」，系统会被恶意文件攻击（路径穿越、磁盘撑爆）。
深层：没有 M3，就没有「用户数据」和「系统数据」的边界。后续所有「按用户隔离」的逻辑都没有依据。整个系统退化成单用户工具。

面试版回答
M3 解决三件事：一是首次引入不可信外部数据的入口，所以需要校验；
             二是建立资源归属模型（documents.user_id），这是后续所有多用户隔离的基础；
             三是为 M4 解析器提供稳定契约（文件在磁盘、记录在库、状态 pending）。
  不用它，不只是「没数据」，而是整个系统的数据边界和多租户模型无从建立。

## 问题2：技术选型为什么？（至少写 1 个"为什么不用 X"）
→ uuid 重命名：防路径穿越/覆盖/中文编码；不用原始文件名。
  1.防路径穿越
    用户传 filename="../../../etc/passwd"，拼路径会得到/etc/passwd写到系统文件，可能覆盖 /etc/passwd（Linux 用户数据库）→ 提权。
    那为什么不用 os.path.basename 剥离路径？safe_name = os.path.basename(file.filename)   # "passwd"
      能防住这个例子，但防不住：
        Windows 的 ..\..\ （反斜杠）

        ..%2F..%2F （URL 编码）

        Unicode 归一化攻击（..／..／ 全角斜杠）

        空字节注入（a\x00.pdf）

        超长文件名（撑爆目录）

        保留名（Windows 的 CON、PRN）
    黑名单永远列不完。 最安全的做法是白名单 + 服务端重命名：不信任任何用户输入，落盘用 uuid。

  2.覆盖
    两个用户都传 报告.pdf，直接存会互相覆盖。uuid 保证唯一（122 位随机）

  3.中文编码
    同时，同一个文件名在不同系统上，字节表示不同。跨平台部署时会乱码、找不到文件、创建重复。uuid 是 ASCII，全局一致。
      Linux ext4：UTF-8
      Windows NTFS：UTF-16
      macOS HFS+：NFD 规范化（é 变成 e + 组合字符）
      某些 NFS：字节序列，看客户端编码

→ 流式写入：1GB 文件不读进内存，边写边算大小；不用 file.read() 一把梭。
  「1GB 不读进内存」，但没说「怎么保证」和「边界」。
   await file.read() 的实际行为：Starlette 已经把文件落到 SpooledTemporaryFile（超 1MB 落磁盘）
  
   .read() 一次性读回内存 → 1GB 文件 → 1GB 内存，10 并发 → 10GB → OOM
   流式写入的实际行为：file.file.read(64 * 1024) 每次读 64KB，写完立即释放，内存恒定 64KB，跟文件大小无关

  「边写边算大小」的意义：不能信任 file.size（客户端可撒谎）不能等读完再判断（已经 OOM 了）只有边读边数才能在「超过阈值」时立刻中断

  「超出即删」的补偿：
    except Exception:
        target.unlink(missing_ok=True)
    不留半成品文件。

→ 本地盘：MVP 单机够；不用 S3/OSS：要密钥/付费/多一层网络，有用户再换。
    
    必须换的信号：

    多实例部署：两个 uvicorn 实例，用户 A 的请求落到实例 1 上传，落到实例 2 下载 → 实例 2 找不到文件

    磁盘快满：日志、备份、其他数据挤空间

    要高可用：单机磁盘坏了，所有文件丢失

    要 CDN：全球用户下载，本地带宽不够

    不换的代价：单点、容量上限、备份麻烦。

    M3 不换的理由：单机、数据少、练手。
