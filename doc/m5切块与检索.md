# 模块 M5 接口契约：解析与切块

## 1. 目标
把 M4 落盘的文本变成**带重叠的定长块**，为 M6 入向量库做准备。
单位是 token（tiktoken cl100k_base），不是字符 —— embedding 与上下文窗口的预算都是 token，
按字符切会让中文文档的块实际 token 数比英文多出 2~3 倍。

## 2. 目录增量 + 表变更
```
app/core/tokenizer.py      # 唯一 token 计数入口：真 BPE 优先，装不上退化为估算并显式暴露后端
app/services/parser.py     # 纯业务：utf-8 → utf-8-sig → gbk 兜底；PDF 走 pypdf
app/services/chunker.py    # 段落 → 句子 → 硬切 三级降级 + 相邻块重叠
chunks 表（新）            # id / document_id / ordinal / text / char_count / token_count
                           # UNIQUE(document_id, ordinal)：保证幂等重跑不会插出两套并列序号
```

## 3. 切块算法（三级降级）
```
按空行切段 → 段落超限则按句切（。！？；换行）→ 句子仍超限则按估算比例硬切字符
再用贪心把单元装进 chunk_size 的预算里，装不下就封块
新块开头接上一块末尾的 overlap 个 token（第一块天然不重叠）
```
- **块大小上界**：不含重叠 ≤ `chunk_size_tokens`；含重叠前缀 ≤ `chunk_size_tokens + chunk_overlap_tokens`。
- `overlap >= size` 时**收紧到 size/4**，不报错：否则滑动窗口原地打转（这是最容易写成死循环的地方）。
- 空文本返回 `[]`，不返回一个空块。

## 4. 编码兜底
顺序：`utf-8 → utf-8-sig → gbk`。为什么不做 chardet 自动探测：多一个依赖、结果不确定、
而我们已知语料只有这三种；并且**猜错时 utf-8 会直接抛 UnicodeDecodeError，不会给你乱码**，
所以显式捕获再换下一个编码是可控的。
BOM 单独剥掉（`lstrip("\ufeff")`）：utf-8 能解码带 BOM 的文件，但第一个块会多一个不可见字符。

## 5. DoD
- [x] 中文 utf-8 / GBK / 带 BOM 三种文件都能读出正确中文（`tests/test_parser.py`）
- [x] 空文件、不支持的后缀、纯图片 PDF 一律失败并带原因（不静默成功）
- [x] 一份长文档被切成 N 块，`ordinal` 从 0 连续（`tests/test_chunker.py`）
- [x] 每块 token 数满足上界；相邻块有重叠；单个超长段落被硬切开

- [x] `/healthz` 暴露 `tokenizer` 后端名（tiktoken 还是估算），避免把估算值当真实值

## 6. 技术约束
- 不引 langchain / 现成 splitter：切块逻辑是本项目的**核心可解释点**，自己写才能答"为什么这么切"。
- 不用 chardet / charset-normalizer（理由见第 4 节）。
- 派生量（char_count / token_count）落库而不是每次算：切块是一次性写入，读侧高频；这是**写入期计算**的典型取舍。
