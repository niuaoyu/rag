# 模块 M6 接口契约：向量入库

## 1. 目标
把切好的块变成向量写进 Qdrant，并保证**多租户隔离**与**可幂等重跑**。

## 2. 目录增量
```
app/services/embedding.py    # HashEmbedder（离线确定性，词面）/ OpenAICompatEmbedder（真语义）
app/services/vector_store.py # Qdrant 封装：ensure_collection / upsert / search / delete_document
```

## 3. 谁存什么（本模块最重要的设计）
| 数据 | 存哪 | 理由 |
| --- | --- | --- |
| 正文（块文本） | **关系库 `chunks` 表** | 事务、级联删除、条件查询的唯一真相源 |
| 向量 | Qdrant | 相似度检索的强项；不做事务 |
| payload | Qdrant：`{chunk_id, user_id, document_id, ordinal}` | 只留**定位信息**，不留正文，避免两处副本不一致 |

代价：检索后要回表取正文（N+1 风险 → 用 `in_` 一次批量取回，见 `retrieval.py`）。

## 4. 两个实现，切换靠配置
| provider | 性质 | 用途 |
| --- | --- | --- |
| `hash` | 字符 n-gram 词袋哈希，**只有词面信息，不是语义向量** | 离线/CI 跑通管道、单测断言"词面相关的块排前面" |
| `openai` | 任意 OpenAI 兼容 `/embeddings` | 唯一语义可用的实现；**检索质量数字只能在它下面产生** |

为什么把 hash 做成正式实现而不是测试里 mock：mock 掉之后向量维度、payload、过滤条件全都测不到；
有确定性的真实现，M6/M7 的测试才测得到真东西。

## 5. 幂等与一致性
- 重跑前先 `delete_document(document_id)` 删旧向量，再 `db.query(Chunk).filter(...).delete()` 删旧块 → 不会检索到上一版内容。
- `ensure_collection()` 发现维度不一致**直接报错**，不静默重建（静默重建会丢数据，且旧向量会污染检索）。

## 8. 在什么条件下会输（技术选型前必写）
- 嵌入式 `path` 模式：**目录独占文件锁**，多 uvicorn worker / 多副本会互相冲突；无副本、无备份 → 上线必须 `QDRANT_URL` 走服务端（Docker 里已配）。
- 单 collection + payload 过滤：租户数到几千、每租户数据量大时，过滤选择性下降、索引效率变差 → 那时应按租户分 collection 或上独立实例。
- 用 hash 向量：任何"语义检索"结论都不成立（已在脚本与文档里显式警告）。

## 9. 实测（2026-10-11，本沙箱）
| 项 | 值 |
| --- | --- |
| Qdrant | `qdrant-client 1.19.1`，嵌入式本地模式，**无需起容器**即可跑测试 |
| 单份文档入库耗时 | ~220ms（含解析+切块+embedding+upsert，hash 档） |
| 向量维度 | hash: 256（配置）；openai: 以接口返回为准 |
| 隔离测试 | 用户 A/B 交叉检索，命中集合严格 ⊆ 自己文档（已通过） |
