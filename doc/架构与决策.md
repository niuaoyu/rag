# 架构与决策（M1–M8 收口）

> 这份文档只写三样东西：**实际怎么跑的**、**为什么这么设计**、**在什么条件下会输**。
> 所有数字都标注来源与产生条件；没测的一律写 UNKNOWN，不许写成结论。

## 1. 数据流（一次问答的完整路径）
```
上传 → 落盘(uuid) → documents 表(pending) → 201 立即返回
                                     ↓ BackgroundTasks
                    process_document: processing → 解析文本 → 存 text
                                   → 切块(chunks 表) → embedding → Qdrant upsert
                                   → done（异常则 failed + error_message）

提问 → query embedding → Qdrant top-k（filter user_id）→ 回表取正文（join 校验归属）
     → 组装带编号的上下文 → LLM（OpenAI 兼容）→ 答案 + citations
```

## 2. 决策清单（每条：选了什么 / 为什么 / 什么时候会输）
| # | 决策 | 为什么 | 在什么条件下会输 |
| --- | --- | --- | --- |
| 1 | 用 `BackgroundTasks` 而不是 Celery | 当前单机、任务秒级；不引 broker 的运维成本 | 需要重试/定时/多机消费/任务可观测时 → 必须换 Celery/RQ；进程崩溃任务直接丢 |
| 2 | 向量库只存向量+定位信息，正文留在关系库 | 避免两处副本不一致；事务与级联删除交给关系库 | 高并发检索时回表成为瓶颈 → 那时考虑冗余正文或加缓存 |
| 3 | Qdrant 嵌入式（本地）/ 服务端（生产） | 本地零依赖，测试无需容器 | 多 worker / 多副本：嵌入式有独占文件锁 → 必须服务端 |
| 4 | 切块单位用 token（tiktoken） | embedding 与上下文预算都是 token | 离线无 BPE 文件时退化为估算（已显式暴露后端，不假装精确） |
| 5 | 三层编码兜底 utf-8 → utf-8-sig → gbk | 已知语料就这三种；猜错会抛异常而非乱码 | 语料出现 Big5/Shift-JIS 等 → 需要换成探测库或扩大链 |
| 6 | LLM 用 httpx 直连 OpenAI 兼容接口 | 只有一个 POST；可 MockTransport 全覆盖测试 | 要接非兼容协议/复杂 function calling → 换 SDK 更划算 |
| 7 | 三种 mode，绝不伪造答案 | 面试一问"这是模型生成的吗"就会崩 | 产品要"永远有回答"的体验 → 需要在 UI 层明示降级，而不是让后端编答案 |
| 8 | 状态只由后台任务改，白名单跃迁 | 路由改状态会出现"接口说 done、任务还在写 text" | 需要人工回滚/重试策略时，白名单要显式扩展并写进文档 |
| 9 | 派生量 char_count/token_count 在写入期算 | 切块是一次性写入、读侧高频 | 解析规则变化后需要回填 → 必须提供 reprocess（已提供） |

## 4.1 真实运行才暴露的三个 bug（测试没测到，面试复盘用）
1. **本地 ONNX 模型 `dim=0`**：ONNX 输出维度动态，构造后不做一次前向就取 `dim` 会得到 0，
   建 Qdrant collection 直接失败。测试里用 hash（维度固定）所以测不到。修法：构造时预热一次前向。
2. **httpx 不读 `SSL_CERT_FILE`**：自签 CA / 企业内网下所有出网请求 `CERTIFICATE_VERIFY_FAILED`。
   修法：显式尊重 `REQUESTS_CA_BUNDLE / SSL_CERT_FILE / CURL_CA_BUNDLE`（`app/core/http.py`），
   **而不是**写 `verify=False`。本沙箱 llm.ujn.edu.cn 的证书连环境 CA 都验不过，
   于是把放宽校验放在**仓库外**的本地转发进程里，产品代码保持严格校验。
3. **`/healthz` 暴露退化档的价值**：`embedding_provider` 是 hash 还是 local、`llm_configured` 真假，
   一眼可辨；否则 demo 时极易把"退化的管道"当成"跑通了"。

## 4.2 另外两个"跑起来才暴露"的坑（都是确定性被环境悄悄破坏）
4. **tiktoken 的 BPE 缓存默认在 `/tmp`，被清理后静默退化为估算**：同一个测试先过后失败，
   根因是 token 计数换了后端（估算与真实 BPE 的边界不同）。
   修法：① `TIKTOKEN_CACHE_DIR` 配置项把缓存固定到项目内目录（`.env` 里指向 `models/tiktoken-cache`）；
   ② `/healthz` 暴露 `tokenizer` 后端名，退化一眼可见。
   **教训**：任何"依赖外部缓存/环境的确定性"，都必须能被观测，否则测试会变成薛定谔的绿。
5. **重叠前缀被"去重"逻辑悄悄吃掉**：原来写的是
   `if tail and not body.startswith(tail): prefix = tail` ——
   语料里段落重复时，`body.startswith(tail)` 会误判成"已经有了"，
   于是重叠没了（跨块答案被切断，正是重叠要解决的问题）。
   修法：重叠**不去重**（重叠本身就是重复），并改成 `tail_within_tokens()` 保证前缀是原文本的
   字符对齐后缀（`decode(encode(text)[-n:])` 会切到多字节字符中间，解出替换符）。
6. **硬切块的上界不能靠"按比例估算切一刀"**：估算与真实计数不是线性关系，切出来仍可能超预算。
   修法：`head_within_tokens()` 二分字符前缀，**由构造保证**每片 ≤ size。
   顺带把上界契约写成 `size + overlap + 1`（+1 是前缀与正文之间的换行符），测试同步收紧。
