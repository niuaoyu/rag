# 架构与决策（M1–M8 收口）

> 这份文档只写三样东西：**实际怎么跑的**、**为什么这么设计**、**在什么条件下会输**。
> 所有数字都标注来源与产生条件；没测的一律写 UNKNOWN，不许写成结论。

## 1. 数据流（一次问答的完整路径）
```
上传 → 落盘(uuid) → documents 表(pending) → 201 立即返回
                                     ↓ BackgroundTasks
                    process_document: processing → 解析文本 → 存 text
                                   → 切块(chunks 表) → embedding → Qdrant upsert
                                   → done（异常则 failed + error_message）

提问 → query embedding → Qdrant top-k（filter user_id）→ 回表取正文（join 校验归属）
     → 组装带编号的上下文 → LLM（OpenAI 兼容）→ 答案 + citations
```

## 2. 决策清单（每条：选了什么 / 为什么 / 什么时候会输）
| # | 决策 | 为什么 | 在什么条件下会输 |
| --- | --- | --- | --- |
| 1 | 用 `BackgroundTasks` 而不是 Celery | 当前单机、任务秒级；不引 broker 的运维成本 | 需要重试/定时/多机消费/任务可观测时 → 必须换 Celery/RQ；进程崩溃任务直接丢 |
| 2 | 向量库只存向量+定位信息，正文留在关系库 | 避免两处副本不一致；事务与级联删除交给关系库 | 高并发检索时回表成为瓶颈 → 那时考虑冗余正文或加缓存 |
| 3 | Qdrant 嵌入式（本地）/ 服务端（生产） | 本地零依赖，测试无需容器 | 多 worker / 多副本：嵌入式有独占文件锁 → 必须服务端 |
| 4 | 切块单位用 token（tiktoken） | embedding 与上下文预算都是 token | 离线无 BPE 文件时退化为估算（已显式暴露后端，不假装精确） |
| 5 | 三层编码兜底 utf-8 → utf-8-sig → gbk | 已知语料就这三种；猜错会抛异常而非乱码 | 语料出现 Big5/Shift-JIS 等 → 需要换成探测库或扩大链 |
| 6 | LLM 用 httpx 直连 OpenAI 兼容接口 | 只有一个 POST；可 MockTransport 全覆盖测试 | 要接非兼容协议/复杂 function calling → 换 SDK 更划算 |
| 7 | 三种 mode，绝不伪造答案 | 面试一问"这是模型生成的吗"就会崩 | 产品要"永远有回答"的体验 → 需要在 UI 层明示降级，而不是让后端编答案 |
| 8 | 状态只由后台任务改，白名单跃迁 | 路由改状态会出现"接口说 done、任务还在写 text" | 需要人工回滚/重试策略时，白名单要显式扩展并写进文档 |
| 9 | 派生量 char_count/token_count 在写入期算 | 切块是一次性写入、读侧高频 | 解析规则变化后需要回填 → 必须提供 reprocess（已提供） |

## 3. 实测数字（2026-10-11，本沙箱：Linux / Python 3.11.2 / 单进程 / 语料 = samples 2 份文档）
| 指标 | 值 | 产生条件 |
| --- | --- | --- |
| 测试 | **82 passed, 0 failed**（19.6s） | `pytest tests -q --ignore=tests/debug` |
| 上传接口响应 | 14ms / 7ms | 立即返回 201，不等解析 |
| 后台管道（解析+切块+embedding+upsert） | **~220ms / 份** | 506 字符 → 492 token → 2 块，hash embedding |
| 切块 | 2 块 / 份（167+388、106+364 token） | `chunk_size_tokens=400, overlap=60` |
| 检索延迟（服务端） | **2ms** | 4 个块，hash embedding |
| 检索延迟（客户端 wall） | 5ms | 本机 loopback |
| tokenizer | `tiktoken:cl100k_base` | 真实 BPE |

## 4. UNKNOWN（明确不知道的，不许猜）
1. **真语义 embedding 下的检索质量**：hit@k / MRR 只有 hash 档数据，**不能作为检索质量证据**（语料仅 4 块，top_k=3）。
2. **真模型回答质量**：本环境 `llm_configured=false`，只验证了 `retrieval_only` 路径与假模型路径。
3. **并发能力**：没有做任何压测 → **QPS / P95 一律没有数字**，不许写进简历。
4. **Docker 镜像是否可构建**：沙箱内**没有 docker**，Dockerfile / docker-compose.yml 属于"写了但未验证"。
5. **估算 token 后端与真实 BPE 的偏差**：本环境 tiktoken 可用，退化路径未触发。
6. **PDF 复杂排版**：只验证了自造的最小 PDF 与空白 PDF；扫描件、双栏、表格抽取效果未测。

## 5. 代码里刻意保留的"防自欺"设计
- `/healthz` 暴露 `tokenizer` / `embedding_provider` / `llm_configured` → 一眼看出当前是真货还是退化档。
- `mode` 三态 → 不配 key 时接口明确说"只给检索结果"。
- `eval_retrieval.py` 在 hash 档打印警告 → 防止把词面重叠当语义质量。
- 测试断言提示词里必须出现 `【资料】` → 防止"检索结果没进 prompt"的静默 bug。
