## 2. 不许写的（现在没有证据）
- ❌ "检索准确率 XX%" —— 只有 4 个块、top_k=3、hash 向量，这个数字不是检索质量。
- ❌ "支持高并发 / QPS XX / P95 XX ms" —— **完全没压测**。
- ❌ "已部署上线 / Docker 化验证通过" —— 沙箱里没有 docker，镜像未验证构建。
- ❌ "LLM 回答准确率 / 引用正确率" —— 本环境没配 key，真模型路径未验证。
- ❌ "处理过 XX 份文档 / 服务过 XX 用户" —— 没有任何真实用户量。
- ❌ "优化了 XX% 性能" —— 没有 before/after 对照实验。

## 3. 简历 V1 草稿（3 条，措辞按掌握度收着写）
```
RAG 知识库问答系统（个人项目 · FastAPI + SQLAlchemy + Qdrant）
· 独立实现文档上传→解析→切块→向量入库→检索→带引用问答的完整链路，
  支持 txt/md/pdf 解析与 utf-8/utf-8-sig/gbk 编码兜底；上传接口 14ms 返回，解析入库异步完成（~220ms/份）。
· 实现 pending→processing→done/failed 状态机（白名单跃迁，状态只由后台任务推进），
  重跑幂等（先清旧块与旧向量）；以 82 个 pytest 用例覆盖解析、切块、向量检索、多租户隔离与问答接口。
· 设计三种回答模式（llm / retrieval_only / no_context）：未配置模型或检索不到内容时明确降级，
  不生成无依据答案；检索结果附文件名、块序号与相似度，答案引用可回溯到原文块。
```
**关于"独立实现"四个字**：主干代码由 AI 辅助生成（我判断方案、验证行为、定位问题）。
