## 2. 不许写的（现在没有证据）
- ❌ "支持高并发 / QPS XX / P95 XX ms" —— **完全没压测**。
- ❌ "已部署上线 / Docker 化验证通过" —— 沙箱里没有 docker，镜像未验证构建。
- ❌ "回答准确率 XX% / 引用正确率 XX%" —— 只人工看了 1 条问答，**没有批量评测**。
- ❌ "处理过 XX 份文档 / 服务过 XX 用户" —— 没有真实用户量。
- ❌ "优化了 XX% 性能" —— 没有 before/after 对照实验（唯一有对照的是上面的检索 A/B，可以写）。
- ⚠️ "检索准确率 90%" 这种说法**不许裸写**：必须带条件（"改写查询基准、156 篇语料、top5、文档级召回"），
  否则面试官一句"哪 20 条题、谁标的"就答不上来。

## 3. 简历 V1 草稿（3 条，措辞按掌握度收着写）
```
RAG 知识库问答系统（个人项目 · FastAPI + SQLAlchemy + Qdrant）
· 实现文档上传→解析→切块→向量入库→检索→带引用问答的完整链路：上传 201 立即返回（8~101ms），
  解析/切块/向量化异步完成；txt/md/pdf 解析含 utf-8/utf-8-sig/gbk 编码兜底，切块按 token（tiktoken 真实计数）。

  改写查询下文档级 recall@5 从 60% 提升到 90%，MRR 0.47→0.64，据此确定语义模型方案。
· 设计 pending→processing→done/failed 状态机（白名单跃迁、状态只由后台任务推进、重跑幂等），
  三种回答模式（llm / retrieval_only / no_context）保证不生成无依据答案；85 个 pytest 用例覆盖
  解析、切块、向量检索、多租户隔离与问答接口。
```
