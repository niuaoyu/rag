Agent 与普通问答系统的区别在于"能不能自己决定下一步做什么"。
一个最小可用的 Agent 循环包含四步：观察当前状态、选择动作、执行动作、把结果写回状态。

工具调用（tool calling / function calling）是 Agent 与外部世界交互的接口。
模型输出一个结构化的调用请求，由宿主程序真正执行，再把执行结果作为新的上下文喂回模型。
这个设计把"决定"和"执行"分开：模型不直接碰数据库和文件系统，权限边界留在宿主程序里。

上下文管理是长任务 Agent 最容易失控的地方。每一步的工具返回都会进入上下文，
几轮之后上下文会被中间结果撑满。常见做法是只保留最近若干轮原文，
更早的内容压缩成摘要，或者把中间结果写到外部存储、上下文里只留引用。

失败处理决定了 Agent 能不能真的用起来。工具调用会超时、会返回格式错误的结果、
会被权限拒绝，这些都不是异常而是常态。工程上要给每个工具设置超时与重试上限，
把失败原因作为可观察的结果返回给模型，让模型有机会换一个动作，而不是直接崩掉整个会话。
