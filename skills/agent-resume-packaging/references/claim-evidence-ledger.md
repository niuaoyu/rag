# 主张—证据账本（Agent 岗版）

账本是这份简历唯一的事实来源。简历、HR 开场白、面试追问都从它派生；任何不能回指账本的句子都不能进最终稿。

可复制 [../assets/claim-ledger-template.json](../assets/claim-ledger-template.json) 作为起点，改完用 `python3 scripts/validate_claim_ledger.py ledger.json` 校验。

## 字段

| 字段 | 用途 |
| --- | --- |
| `id` | 稳定引用，例如 `claim-agent-001`；简历里用 `【证据：claim-agent-001】` 回指 |
| `source_fact` | 原始事实，不做包装。允许写得很土，例如「把工具调用统一到一个注册表，参数校验和超时都在里面做」 |
| `candidate_wording` | 候选措辞，简历可以直接用；`待确认` 时必须含 `【待补：...】` |
| `sources` | 证据位置：相对路径、测试文件与条数、可复现命令、轨迹文件、PR 链接 |
| `responsibility_level` | `参与` / `负责模块` / `主导方案或交付` / `项目负责人` |
| `verification_status` | `已确认` / `待确认` / `已过期` / `不采用` |
| `allowed_uses` | 可用于哪些岗位版本，例如只投 Agent 岗、不投纯后端岗 |
| `interview_details` | 能在追问里展开的决策、取舍、失败路径、验证方式（强主张必填） |
| `boundary` | 团队成果与个人贡献的分界；AI 结对完成的部分要写清 |
| `risk_notes` | 冲突、缺口、投递前必须处理的问题 |
| `last_verified` | 最近一次确认日期（YYYY-MM-DD），未知写 `null` |

## Agent 岗特有的三类事实

包装 Agent 项目时，最容易「看起来假」的是把**框架名词**当成**个人能力**。事实层至少要能回答：

1. **编排机制**：工具怎么声明、怎么校验参数、怎么限时、失败怎么收敛、步数怎么限。证据来自编排层代码 + 覆盖这些路径的测试。
2. **边界与降级**：模型不可用、工具报错、预算耗尽分别返回什么。证据来自降级分支的测试用例。
3. **可观测**：一次运行留下了什么（轨迹字段、耗时、错误），能不能据此复盘。证据来自轨迹文件与写轨迹的测试。

只有「接了 LangChain / 调了某个模型」而没有以上三类事实时，`responsibility_level` 只能写 `参与`，措辞也必须停在「接入/试用」。

## 状态规则

- **已确认**：有 `sources` 且你能现场演示（跑测试、打开文件、出示轨迹）。可以进正式稿，但仍保留 `boundary`。
- **待确认**：只有描述没有证据，或你记不清细节。只能出现在草稿里，且 `candidate_wording` 必须含 `【待补：...】`。
- **已过期**：曾正确但会变，例如「在读」「在投」「Star 数」。更新前不得使用。
- **不采用**：确认不准确、与岗位无关，或你不想公开。保留原因便于复盘。

## 强主张与追问的对应关系

出现「主导 / 负责人 / 从 0 到 1」时，`interview_details` 必须能回答：

- 为什么这样设计？备选方案是什么？为什么放弃？
- 关键取舍在哪？失败路径长什么样？你怎么发现的？
- 怎么验证有效？如果没测过，你打算怎么测？

回答不了就把 `responsibility_level` 降级——降级不会让你显得弱，答不上来才会。

## 交付检查

- [ ] 对外材料里每个强主张都能回指一条账本记录。
- [ ] 最终稿不含 `待确认` / `已过期` / `不采用` 的主张。
- [ ] 指标写明口径与时间，不把项目总量当成个人数据。
- [ ] 账本里没有密钥、口令、客户数据、内部未公开材料。
- [ ] 修改措辞时更新 `candidate_wording`，不篡改 `source_fact`。
